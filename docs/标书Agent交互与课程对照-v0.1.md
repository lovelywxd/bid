# 标书 Agent 交互与课程对照 v0.1

日期：2026-11-12。状态：产品设计，尚未实现。配套：[需求规格](标书Agent需求规格-v0.2.md)、[实施计划](标书Agent实施计划-v0.1.md)。

## 1. 采用的方案

采用“项目工作台＋常驻对话＋可定位的正文/要求/问题对象”。用户通过自然语言提出目标、追问和修订，也可直接编辑及点击业务动作；两种入口调用同一套任务、版本和验收服务。

| 方案 | 对本项目的取舍 |
|---|---|
| 全屏聊天，标书作为消息附件 | 提出目标方便；整本编辑、证据对照、问题追踪需要额外找回产物，不作为默认布局 |
| 表单/步骤页驱动 | 状态和固定操作明确；临时追问与定向修订需频繁切换，保留为结构化操作入口 |
| 项目工作台＋对象关联对话 | 同时看到产物、依据和操作结果；作为首版默认，折叠面板支持专注阅读 |

以上是本项目的设计选择，尚未通过用户测试证明效率收益。首版不建设流程拖拽编辑器、角色聊天室或任意工具市场。

## 2. 吴恩达课程参考与适用边界

已核对 DeepLearning.AI 官方《Agentic AI》的公开课程介绍和大纲，讲师为 Andrew Ng；不是完成全部视频、付费作业或代码实验。大纲包括任务拆解、自主程度、Reflection、Tool use、Planning、Multi-agent，以及整体/组件评估、错误分析和成本优化。[S1]

| 参考方向 | 本项目的具体采用 |
|---|---|
| 任务拆解与规划 | 先固定业务阶段和验收门，再由模型规划大纲、条款组、检索及修复动作；计划必须写回可执行任务 |
| Reflection 与外部反馈 | 写作后对照原始条款、企业证据、程序规则与人工反馈复检；每次反馈有问题位置和修改目标 |
| Tool use | 提供范围受限的检索、原文读取、章节修订、问题处理工具；动作由服务校验并持久化 |
| 组件评估与错误分析 | 分别测解析遗漏、要求抽取、证据支持、上下文交接、修订和文件质量；根据错误来源决定下一步 |
| 自主程度与多 Agent | 正常步骤自动推进，关键事实/决定和交付由人确认；首版单 worker 分角色调用，暂不并行自治写作 |

右列是本项目的落地推导，不是课程给出的标书架构或界面。任务分角色与部署多个自治 Agent 是两回事；是否并行以后按依赖、事实一致性、质量和成本对照结果决定。

另参考 Anthropic 对 workflow/agent 的区分、中间检查门和 evaluator–optimizer 模式：[S2] 用固定业务流程组织阶段，节点内允许模型根据工具结果调整动作。本项目不把循环次数、评分阈值或框架选择归因于课程。

## 3. 对用户流程图的修正

| 图中环节 | 采用方式 |
|---|---|
| 提取星号条款与评分细则 | 还须覆盖普通实质性条款、表格条件、附件及提交要求；回查原始页/对象台账 |
| 缺资质触发 Interrupt | 先区分没检索到、事实待核、确认不具备；只暂停依赖任务，其余继续 |
| 蓝图与带权大纲 | 保留要求到正文/附件的映射；权重依据招标规则，无规则时不编造分数 |
| 多 Writer 并行 Map–Reduce | 首版按节串行执行并独立装配上下文，父级核对覆盖与承诺；不能直接拼接多个自由生成稿 |
| 模拟评委打分与阈值 | 模型语义审核是检查手段之一；硬性阻断、待核项、未检范围、版本有效性优先于总分 |
| 重写循环 | 按原因路由到重解析、补抽、检索、补事实、改正文或重渲染；保留次数、问题和差异 |
| 达标即导出 | 最终 DOCX 渲染后还要验收，人工放行绑定审核版本和文件哈希 |

修正后的流程：选知识版本 → 导入本项目文件 → 解析/要求/证据校验 → 大纲、本节方案与细目录校验 → 代表小样验收 → 分节 Do–Check–Loop 及客户语言编辑 → 分批全文审核 → Word 装配/渲染/校验 → 人工放行。任一步失败均有局部回路及待处理出口。写前方案、内容展开与正负约束的具体检查见[内容质量与写前设计](标书Agent内容质量与写前设计-v0.1.md)。

## 4. 用户入口与界面

全局导航：项目、产品与知识库、记忆中心、设置。设置内含模型连接、模型用途、Agent 执行策略、存储与备份。

新建项目用一张启动卡完成：项目名/卷册、产品/已发布知识版本、招标与补遗附件、特殊目标、执行配置。自然语言可辅助填写；开始前展示确认后的项目范围与待填项。已有有效知识无需重复上传。

项目打开后采用三栏布局：

```text
┌──────────────────────────────────────────────────────────┐
│ 项目 / 知识版本    当前阶段 · 已验收/待核     暂停 / 交付   │
├────────────┬────────────────────────┬────────────────────┤
│ 章节/待办  │ 工作区                 │ 标书助手           │
│            │ 正文｜矩阵｜问题｜预览 │ 项目对话与行动卡   │
│ 2.1 已验收 │                        │                    │
│ 2.2 待处理 │ 可编辑正文 / 版本差异  │ 缺什么、影响哪里   │
│ 2.3 检查中 │ 点引用打开原文对照     │ 做了什么、复检结果 │
│            │                        │                    │
│ 项目资料   │ 当前选择可关联到对话   │ [本节] [所选问题]  │
│ 项目记忆   │                        │ 输入指令 + 附件    │
│ 运行记录   │                        │               发送 │
└────────────┴────────────────────────┴────────────────────┘
```

正文占主要空间；左侧目录、右侧助手均可折叠。原文对照复用工作区或抽屉，不再永久增加第四栏。对话不只显示长段回复：返回可打开的产物、问题卡、差异卡、补件卡和验收结果。页面上的数量和状态从业务库读取，不由模型自由描述。

正文旁提供“本节方案”页签，展示拟解决的业务问题、解决机制、细目录/展开计划、依据与待决项。矩阵分开呈现覆盖、解释充分性和证据状态；“生成了草稿”与“内容已验收”分别显示。

新项目以启动卡和目标输入为主；制作中以正文和助手为主；遇到阻塞突出待办；审核时切问题列表/差异；交付时切最终文件预览。所有阶段沿用同一项目对话和状态。

## 5. 对话能做什么，怎样避免误操作

| 用户表达 | 处理与产出 |
|---|---|
| “这条要求的依据在哪？” | 只查询，返回原条款、企业证据及对应正文；不触发修订 |
| 选中段落说“缩短这一段，保留承诺和数值” | 固定块 ID/正文版本，生成局部差异，校验后采用并重新审核受影响对象 |
| “检查全文服务期限是否一致” | 新建跨章核查任务，输出引用和问题；没有改写授权时不改正文 |
| “把刚才发现的期限矛盾修好” | 按具名问题及已确认决定定向修订；缺少决定先出确认卡 |
| “本项目确认采用单中心部署” | 生成带范围和影响的项目决定确认卡；用户确认后建立版本，触发相关复核 |
| “以后少写宣传性套话” | 显示项目/企业/通用适用范围，确认后保存写作经验；不作为产品能力事实 |
| “继续” | 恢复当前可执行任务；缺口、事实确认和最终放行仍按各自条件处理 |

对话请求携带 Conversation/Message ID、request_id、项目/基线、所选对象与 expected_revision。输入框显示作用范围标签：选中块、当前节、项目；请求“全文”可以扩大目标，但须在行动卡明确显示。指代不明或对象已变化时澄清，不能猜另一个章节执行。

服务生成 ActionRequest：意图、对象/版本、依据、预期产物、允许动作和预算。只查询的请求不改业务状态；明确授权的局部修订可自动执行与验收，不要求用户逐步点同意。新事实/决定、知识版本采用、锁定解除、预算增加和最终放行使用带对象版本的明确确认；确认不允许越过实质性不满足等硬门槛。

动作显示 queued/running/checking/accepted/waiting_input/failed/stale，并关联实际 task_id、产物及 ValidationReceipt；对话文字不直接宣告数据库未发生的成功。重复发送、SSE 重连、重复点确认均幂等；过期卡片失效。图中或附件中的指令属于资料内容，不能成为用户授权。

后台运行时仍可追问或发补充指令。查询单独执行；变更请求在安全提交点协调，当前调用不被假称撤销。旧版本迟到结果保留候选，不能覆盖用户新改稿。阶段切换、折叠助手和关闭页面都不取消后台任务；“暂停/取消”的实际范围与生效状态明确显示。

对话保留项目级时间线，按章节/问题可筛选。新会话仍绑定原项目；历史消息只供审计/按需检索，执行时重新装配结构化记忆及当前证据，不把整段聊天持续附加给模型。展示动作、依据及结果，不要求展示模型内部推理。

## 6. 模型设置和记忆管理

模型设置保存提供商/API 地址、凭据引用、模型名、用途映射、能力检查结果、上下文/输出预算、超时、费用及可发送资料范围。首版实现一家提供商适配；分析/写作/审核/摘要可共用模型，embedding 单独配置。连接与能力测试结果区分通过、失败、未测，测试未通过的用途不能启动相应任务。

API Key 由后端写系统凭据库，数据库只存引用；页面仅显示掩码，响应、日志和导出不返回密钥。非敏感配置以不可变版本保存，run/task 绑定实际版本；更改默认值不改变在途调用。明确采用新配置时从安全节点生效并重建上下文；预算不重置，embedding 变化须另建索引。

记忆中心分项目约定、已确认表达经验、候选经验；企业事实仍由知识库维护，中心提供关联查看。每条可查看来源、范围、版本、确认状态和使用位置；支持纠正新建版本、确认或停用并预览影响。当前节的“使用依据”展示本轮条款、事实、决定及经验引用。

| 数据 | 存储与管理 |
|---|---|
| 事实、决定、经验、对象关系、对话及行动记录 | PostgreSQL；可从对应业务入口查看，修改产生新版本 |
| 摘要、ContextManifest、ContextSnapshot、验收及恢复位置 | PostgreSQL/checkpoint；自动维护，运行详情可追溯，不允许手改进度冒充完成 |
| 原件、大工具结果、正文快照附件、Word/PDF | 本地持久文件目录；数据库存哈希与引用 |
| 检索向量 | pgvector；是可重建索引，不取代原文和事实记录 |

业务记忆独立于所选模型会话保存。备份覆盖业务库和文件；凭据不进入普通项目导出，迁移后重新配置或单独安全恢复。

## 7. 实施与验收

先交付“启动卡＋基本对话＋章节工作区＋行动/验收卡”，串通少量真实章节；设置和知识库基础入口随对应后端任务完成。后续完善全文矩阵、影响分析、版本对照与交付中心，不先建设通用聊天平台。

新增验收场景：T21 模型配置版本/凭据与运行隔离；T22 经验/决定确认及变更传播；T23 查询不改正文；T24 选择范围与并发改稿；T25 重复确认、暂停恢复和对话交接。详细结果见需求规格，任务映射见实施计划。

界面验证至少覆盖：首次创建并启动项目、从问题定位原条款与证据、选中内容定向修订、补充缺口后继续、发现旧审核失效、最终放行。记录完成率、错改对象、找依据的操作、主动操作时间及人工修正次数；与纯聊天/固定步骤页对照后再判断交互收益，不用主观“像 Agent”作为验收。
