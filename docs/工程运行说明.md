# 工程运行说明

当前工程是本机开发工作台，默认 SQLite、合成资料和模型替身。Harness 仍通过实际 SDK、CLI 和插件执行组合流程；这不代表已经验证真实模型或真实标书质量。

## 首次准备

在仓库根目录执行。当前安装脚本的工具链包含 macOS ARM64 的嵌入式 PostgreSQL，其他平台需要先适配 `infra/toolchain/` 和相关脚本。

前置工具为 Git、Python 3.11–3.13、`uv`、`npm` 和 `make`。安装时 `uv` 选择 Python 3.13，npm 安装项目隔离的 Node 24.11.1 和 pnpm 11.28.5。

```bash
make bootstrap
```

此步骤需要网络，会安装锁定依赖，拉取固定 SHA 的 DeepSeek Harness、应用仓库补丁、执行官方构建和构建检查，再构建插件与前端，生成 `runtime/builds/active.json`。固定上游 SHA 为 `e8f7b93a344964de3dca1ace9e72b6e4d6de87cb`，补丁说明见 `runtime/upstream-patches/README.md`。

已经安装依赖和构建上游后，修改插件、配置或前端可执行：

```bash
make build
```

`make build` 不安装依赖，也不重新执行官方 Harness 构建。修改上游补丁或更新锁定版本时需重新构建 Harness。清单包含本机文件路径和哈希，换机器后应重新生成，不应从其他机器复制清单。

## 启动工作台

```bash
make dev
```

启动脚本执行数据库迁移，然后启动 API 和 Worker；前端构建由 API 提供静态文件服务。浏览器打开 `http://127.0.0.1:8765`，接口文档为 `/docs`，健康检查为 `/api/health`。按 Ctrl-C 结束本次启动的进程，数据保留。

SQLite 数据库默认位于 `data/bid.db`。需要本机隔离 PostgreSQL 时执行 `make dev-postgres`，使用 `data/postgres/` 和 `127.0.0.1:55432`。`infra/compose.yml` 也提供 Docker PostgreSQL 备选，二者不能同时占用同一端口；Docker 数据库需用 `BID_DATABASE_URL` 显式指定连接串。

## 环境变量

| 变量 | 用途与默认值 |
| --- | --- |
| `BID_DATA_DIR` | 本机运行数据目录，默认根目录下 `data/` |
| `BID_DATABASE_URL` | SQLAlchemy 连接串，默认指向 `BID_DATA_DIR` 下的 SQLite |
| `BID_RUNTIME_MODE` | 运行模式，默认 `fixture`；`infra/dev.py` 固定为此模式 |
| `BID_TEST_POSTGRES` | 可选测试数据库连接串，设置后测试额外覆盖 PostgreSQL，并创建、删除隔离测试 schema；只指向专用测试库 |
| `BID_CHROME_PATH` | Playwright 浏览器路径，默认 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` |

配置通过进程环境变量传入；代码不会自动读取 `.env`。当前运行入口与许可补丁面向本机模型替身，填入真实 API Key 不会自动启用真实模型支持。

## 检查与评测

```bash
make check          # 后端业务/迁移测试、前端构建、插件类型检查
make test           # 全部后端测试，包含实际 Harness 的组合测试
```

组合测试需要先完成 Harness 构建和本机清单生成，使用临时数据库与本机 HTTP 替身；测试生成的会话与请求证据位于 `evals/results/stage1/`。

浏览器场景需要已构建前端、启动 API 和 Worker，并安装 Chrome。先在一个终端运行 `make dev`，再在另一个终端运行：

```bash
make e2e
```

浏览器测试会创建并保留合成项目及相关记录。`make smoke` 同样会向运行中的服务写入合成项目并排队任务，其输出仅证明请求已被接收；任务最终状态需要在工作台中核对。

## Git 收录范围

收录业务源码、Skill、需求与研究文档、锁文件、构建脚本、配置和上游补丁。以下内容保留本机但不收录：

- `.tools/`、Python 虚拟环境、`node_modules/` 和 `dist/`。
- `runtime/builds/` 内的上游源码、依赖、构建产物与本机清单。
- `data/` 中的数据库、原始资料、会话和请求日志。
- `evals/results/`、Playwright 报告和各种测试缓存。
- `.env`、私钥和机器专用配置。

需要长期保留的验收结论应整理成脱敏文档，放入 `docs/`，同时说明执行范围与未验证项；不要直接提交完整运行目录。
