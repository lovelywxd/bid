# 独立标书 Agent 需求规格 v0.2

日期：2026-11-12。配套：[实施计划 v0.1](标书Agent实施计划-v0.1.md)。

本文是本次实施计划的需求工作基线，替代 v0.1 草案用于任务拆解。独立 Agent、完整业务流程、上下文与记忆管理来自用户方向；首版范围、技术方案和数值目标是本次规划建议，不表示已由用户逐项确认，也不表示已开始开发。

## 1. 产品目标

建设一个接入大模型的独立标书应用。产品与企业知识库长期维护并跨项目复用；每次投标选择产品及知识库版本，提供本项目招标文件、补遗和特殊约定。Agent 组织要求、证据、写作、审核、修订与导出，减少人工调度、重复提供背景和返工。

完整闭环的判定：要求有响应去向且按业务需要讲清楚，章节方案与细目录有依据，关键事实和正负向约束有依据，缺口能补充后继续，变更能触发复核，最终交付文件与验收版本一致。粗稿生成与内容验收分别显示，不以目录完整或篇幅代替质量。

## 2. 首版范围

| 项目 | 本次计划采用的范围 |
|---|---|
| 使用方式 | 单人、单企业、本机 Web 应用；界面与服务仅监听本机地址 |
| 项目管理 | 保存和切换多个项目；首次只运行一个项目的生成任务 |
| 首个交付 | 一种真实业务场景的中文技术标；行业与产品由试点材料确定，不默认 DHR |
| 全项目要求 | 识别技术、资格、商务、格式、附件和提交要求；卷册外要求注明责任与去向 |
| 输入 | DOCX、文字型 PDF、扫描 PDF、PNG/JPEG；正文、表格、图片均需处理状态 |
| 企业资料 | 产品说明、资质、案例、人员资料、模板和历史标书；保留来源与适用范围 |
| 知识库入口 | 独立管理产品、版本、公共资料及发布状态；初始化后增量维护，项目引用已发布版本，不重复上传 |
| 输出 | 可编辑 DOCX、对应 PDF 预览、响应矩阵、审核报告、版本与验收清单 |
| 编辑 | 应用内按章节和内容块编辑、比较版本、锁定内容；Word 外改稿须重新导入审核 |
| 模型 | 接入一家真实模型提供商；配置可替换；正文与审核任务分开调用 |
| 交互 | 项目工作台＋常驻对话；支持对象关联指令、直接编辑、行动卡与验收结果，统一调用业务服务 |
| 设置与记忆入口 | 模型/执行配置独立管理；项目记忆和经验可确认、纠正、停用及查看影响 |
| 自动化 | 正常任务自动推进；缺依据、关键决定、预算耗尽或反复修订无效时转待处理 |

首版不包含：自动报价决策、电子签章、投标网站提交、多用户实时协作、通用行业模板市场、多个自治 Agent 并行讨论、模型训练、Word 任意修改后的无损回写。

## 3. 主流程与人工职责

长期维护并发布产品/企业知识库 → 创建项目并选择知识库版本 → 上传本项目招标文件和补遗 → 解析与核对 → 提取要求与评分规则 → 匹配企业证据 → 大纲、本节方案与细目录校验 → 代表小样验收 → 分节写作、展开深度/承诺核验与客户语言编辑 → 全文审核与修订 → Word 装配及渲染检查 → 人工放行。

标书制作是一个持久化长任务；每节或条款组是可独立恢复的子任务。每一步均执行“确定输入与验收条件 → Do → 检查实际产物 → 通过提交或按问题 Loop”，不以模型调用成功代表业务完成。检查未通过的产物保留为候选或异常记录，不作为已经验证的上游输入。

Agent 负责查材料、组织任务、生成草稿、发现问题和执行已约定的修订。用户负责无法从材料确认的事实、商业决定、关键承诺、大纲/小样和最终放行。沿用已确认约定时不重复确认。

缺口仅阻断依赖该信息的任务；其他任务继续。找不到材料、无法判断、不满足要求必须分别记录。技术标可独立导出，但不得据此声称资格标、商务标或整个投标项目已合格。

## 4. 功能需求

| 编号 | 必需能力 | 验收结果 |
|---|---|---|
| F01 | 项目与交付范围 | 项目有企业、客户、卷册、资料基线和责任范围；切换项目不串资料 |
| F02 | 资料与版本 | 原件保留哈希、来源、范围和版本；同名不覆盖，重复上传不重复建立有效版本 |
| F03 | 结构解析 | 正文、表格、图像和读取顺序可回查；每页/对象的成功、异常、未检查状态可见 |
| F04 | 要求与评分台账 | 条款有原文、条件、类别、卷册、评分规则和生效版本；不只抽取带星号条款 |
| F05 | 企业事实与证据检索 | 产品、版本、资质有效期和案例适用范围参与筛选；返回可打开的原文 |
| F06 | 大纲与写作任务 | 每项要求映射正文、附件或卷册外责任；每节明确要求、证据、约定与缺口 |
| F07 | 分节写作 | 只使用当前基线和有效依据；历史标书仅参考写法，事实须重新核验 |
| F08 | 缺口与补充恢复 | 缺口记录依据、影响、所需材料与阻断范围；补充后复核并恢复对应任务 |
| F09 | 章节审核与修订 | 问题有位置、依据、严重度、修改目标和复检结果；修订有上限并保留历史版本 |
| F10 | 全文审核与估分 | 逐要求复查，检查跨章承诺、附件和串稿；估分标明依据、区间和未知项 |
| F11 | 变更影响 | 补遗、资料、事实、决定或正文变化使相关任务、审核和交付候选失效；不确定时扩大复核 |
| F12 | 人工编辑保护 | 内容块可锁定；生成期间人工修改不被覆盖，冲突结果进入候选区 |
| F13 | 可恢复运行 | 暂停、重启、重复恢复保留已提交成果；失败定位到任务，重复执行不重复提交 |
| F14 | Word 与视觉验收 | 图片、表格、目录、编号、页眉页脚和分页可用；有实际渲染记录及检查范围 |
| F15 | 交付与放行 | 区分草稿、候选和已放行；放行绑定要求、正文、审核、渲染版本和文件哈希 |
| F16 | 进度与成本 | 查看阶段、问题、尝试次数、模型、实际用量与失败原因；估算、实测和未知用量分开 |
| F17 | 全步骤产出校验 | 每个步骤有输入版本、产物、校验器、检查结果与失败去向；校验不完整、失败或失效时不能晋升为已验收产物 |
| F18 | 长任务拆分与上下文压缩 | 按节/条款组拆任务并重建上下文；摘要保留来源、条件和未决状态；换会话及压缩不丢关键约定，不静默截断 |
| F19 | 纠错循环与验收协议 | 依据问题选择重解析、检索、重建上下文、修订、补充或重渲染；复检后才采用候选；章节、整本、文件逐层验收，达到上限不算通过 |
| F20 | 模型与 Agent 设置 | 可测试连接和用途能力、保存版本化配置及预算；运行绑定实际版本，凭据不出现在日志或导出，在途任务不随默认值静默切换 |
| F21 | 记忆管理 | 可查看事实/决定/经验的来源、范围、版本和使用位置；候选确认、纠正及停用有记录，变更传播复用 F11，不由聊天自动确认能力事实 |
| F22 | 对象关联对话 | 查询、修订及确认意图区分；选择与作用范围可见；动作绑定业务对象版本，返回实际产物/验收记录，重复执行幂等且不覆盖人工新稿 |
| F23 | 写前方案与细目录 | 正文前保存本节业务问题、方案机制、来源/决定、细目录及展开计划；按章节类型校验，方案不成立不能只润色后过关 |
| F24 | 内容展开与客户表述 | 覆盖、解释充分性和证据状态分别记录；检查细目录拼点、空泛展开、作者说明/翻译腔、无依据正向承诺及擅加限制；人工批准的缺陷样例参与回归 |

## 5. 上下文与记忆

### 5.1 保存边界

| 信息 | 使用规则 |
|---|---|
| 原始材料 | 不可覆盖；原文是证据，摘要只用于导航 |
| 企业事实 | 记录证据、版本、有效期、适用范围和确认人；模型推测不自动生效 |
| 项目决定 | 记录客户、术语、范围、架构、工期、服务期等约定及确认来源 |
| 执行状态 | 要求、依赖、章节、缺口、问题和运行位置由数据库保存 |
| 正文与交付 | 逐版保存；草稿、模型评审意见不能自动成为企业事实 |
| 写作经验 | 人工修订原因和表达偏好进入候选经验；确认范围后才可跨项目使用 |

### 5.2 每次调用的上下文

按任务装配当前要求原文、有效证据、相关决定、章节依赖、未决问题及必要参考，记录实际使用的版本与省略原因。审核可重新读取原始材料，不依赖写作者的覆盖结论。

必需条款装不下时拆任务，不静默截断。聊天用于交互与审计，不作为唯一记忆。更换模型会话后仍应恢复同一项目约定和任务状态。

采用“持久化父任务＋按节/条款组的独立上下文＋结构化记忆＋受控摘要”。跨节共享已确认的项目约定和具体版本引用，不连续传递所有前文。章节摘要、资料摘要和执行交接摘要分别管理，均是可重建的派生数据；关键条款、数值、否定、例外条件、待核状态和来源引用不能被自由概括覆盖。

压缩优先清理重复工具输出、按 ID 回读原文、移除无关参考，再生成带来源的交接摘要。仍超预算则拆分任务；不让摘要替代关键要求和事实核验。摘要及恢复过程本身也必须校验，发现遗漏、版本过时或确认状态变化则重建。

### 5.3 变更原则

原始文件、事实、决定和正文均采用新版本替代旧版本。变更时撤销受影响的当前审核有效性；旧交付保留当时记录，新交付必须重新核对。人工锁定内容与新要求冲突时提交问题，不自动改锁定内容。

## 6. 审核与交付规则

1. 分开检查：程序可核对的结构/标识/数值、逐要求和逐承诺的语义、需要人工判断的质量。
2. 关键要求漏项、无依据硬承诺、串项目、卷册隔离错误、关键页面不可读，属于放行阻断项。
3. 模型高分不能抵消阻断项；评审结果不能代替企业事实确认。
4. 实质性要求缺依据时，改成模糊措辞不算解决；无法确认则保留未决状态。
5. 初始每节最多两轮自动内容修订。缺证据、同一问题反复或费用不足时进入待处理，不无限重写。
6. 重要问题须解决或有具名的人工风险接受记录；明确不满足的实质性条件不能登记为已满足。
7. 生成 Word 后还需检查成品。导出、渲染和放行必须指向同一文件版本。
8. 外部编辑后的 Word 不继承原放行；重新导入为交付候选，完成差异审核与渲染后再放行。
9. 每轮先保存候选，再针对验收契约核对目标问题、受影响对象和新增缺陷；通过后提交有效版本。审核器自身的输出也校验引用、对象版本和检查范围，检查服务异常进入待核。
10. 修订依据具体问题路由，Loss 用于质量比较和处理优先级；阻断项、关键待核项、未检范围和版本有效性优先于总分。评分标准固定版本，不允许为过关删要求、缩小检查范围或放宽门槛。
11. 每个步骤的验收规则和实际证据见实施计划第 4.6—4.9 节；检查方式区分程序、模型语义和人工判断，不宣称程序可自动证明所有事实或语义正确。
12. 内容验收采用[内容质量与写前设计](标书Agent内容质量与写前设计-v0.1.md)的分类型判据；关键业务问题未回答不能仅凭关键词覆盖通过，不为增加深度虚构功能或新增条件。语言润色后重新核对语义差异；真实必要的否定、限制与偏离不能被风格过滤隐藏。

## 7. 验收场景

| 编号 | 输入/操作 | 必须观察的结果 |
|---|---|---|
| T01 | 正常资料完成成稿 | 要求、依据、章节、审核与交付可串联回查 |
| T02 | 关键要求位于表格或扫描页 | 保留条件、单位和表头；漏读或不确定被显式报告 |
| T03 | 缺少关键证书，随后补齐 | 不编造、不误判企业能力；其他任务继续，补齐后恢复 |
| T04 | 历史标书含其他客户和旧承诺 | 可参考表达，不带入身份、旧数值或未验证能力 |
| T05 | 多个产品版本或过期证书 | 选择适用版本；冲突、过期或无法确认形成问题 |
| T06 | 补遗将服务期三年改为五年 | 相关正文、计划、附件和审核进入待复核；旧候选不能放行 |
| T07 | 前文单中心、后文同城双活 | 定位矛盾并依据项目决定处理，不自行合并成模糊说法 |
| T08 | 人工修改并锁定段落 | 自动修订保留锁定；新要求冲突时等待人工处理 |
| T09 | 中断、重启、重复恢复 | 当前版本正确、成果不重复提交、进度可恢复 |
| T10 | 审核通过后再修改正文 | 旧审核失效，新导出与新审核一致 |
| T11 | 切换项目并检索 | 不出现其他项目的私有事实、客户名、草稿或待办 |
| T12 | 模型失败、预算耗尽、修订无效 | 保留可靠版本，停止受影响任务，说明原因并可恢复 |
| T13 | 输出包含图片、复杂表格和目录 | DOCX 与 PDF 可读，检查所有页面并记录缺陷处理 |
| T14 | 某个步骤返回格式正确但引用不存在或条件错误 | 拒绝晋升；记录依据并路由修复，不因 JSON 合法判定通过 |
| T15 | 任务输入接近预算，含例外、数值和待确认事项 | 清理/压缩或拆分后关键内容与来源保留；未确认不变成确认；超限不截断 |
| T16 | 多次压缩并在新会话恢复 | 能从持久状态和原始引用恢复；进度、承诺、锁定内容和未决问题一致 |
| T17 | 正文或知识版本改变，旧摘要仍在缓存 | 依赖校验拒绝旧摘要；重建后才继续；知识库更新不静默改变既定项目基线 |
| T18 | 小节通过但章节或全文存在矛盾 | 父级验收失败；按影响范围生成修复任务，不以子任务全绿代替整体验收 |
| T19 | Loss 降低但新增无依据承诺，或通过删问题使分数改善 | 新候选不获验收；冻结规则、检查范围和原问题记录保持可回查 |
| T20 | 检查器失败、修订无进展或重复拆分恢复 | 检查结果不伪报通过；预算/修订计数不因换会话或拆分重置；转待处理 |
| T21 | 配置连接失败、用途未测、运行中更改默认模型或导出配置 | 未通过测试的用途不启动；在途调用仍绑定原配置，显式切换从安全节点生效；密钥不泄露，预算不重置 |
| T22 | 对话提出项目决定/跨项目偏好，随后纠正或停用 | 显示来源和范围并经明确确认；不把偏好登记为能力；变更后相关记忆/正文/审核重新核验 |
| T23 | 询问条款依据或要求检查全文 | 返回来源或检查任务，不擅自修订、关闭问题或放行；行动结果可回查实际任务和记录 |
| T24 | 选中段落修订，期间人工改稿或切换章节 | 请求保留原对象/版本与范围；指代不明先澄清，旧结果进入候选；不改错章节或覆盖新稿 |
| T25 | 重复发送/点确认、SSE 重连、暂停后新对话恢复 | 不重复提交事实/正文/放行；过期卡片拒绝执行；从业务状态恢复，待核项不丢失，预算不刷新 |
| T26 | 总体方案、详细功能和实施章节资料充足或关键依据不足 | 写前形成适用的方案/展开设计；缺依据补读或待核，不用抽象口号掩盖；关键方案检查通过后才生成正式候选正文 |
| T27 | 高层目录正确，细层拼接无关点或机械拆标题 | 依据完整业务问题重组细目录，保留招标规定目录和所有条件；不以层级更多判为更优 |
| T28 | 内容涵盖关键词但未解释业务过程；对照长篇重复稿和有据展开稿 | 分别报告覆盖/展开/证据状态及未回答问题；重要说明缺失时拒绝内容验收，不因篇幅长或术语多获通过 |
| T29 | 作者说明、修辞对比，与必要否定/真实限制混合 | 改为直接面向客户的业务表述；保留真实条件和范围，差异复检不改变承诺，不靠关键词一刀切 |
| T30 | 草稿新增无依据功能保证、自设排除项、客户义务或指标 | 定位正负约束并回查来源/必要性；可选无据内容删除，必须响应的条款不得删回答逃避；已批准缺陷进入后续同类章节回归 |

工程故障测试可以使用合成材料。业务效果验收必须使用真实或经授权脱敏的材料和人工核对基准，不能由模型自评分代替。

## 8. 试点成功标准

- 工程门槛：T01—T30 全部执行；无未解决的放行阻断项；人工编辑不丢失、项目不串资料、旧审核不误放行。
- 材料门槛：验收材料中所有人工标记的关键要求均有可核查去向；不能用已提取条款数量充当完整分母。
- 交付门槛：至少一份真实项目整本技术标及其响应矩阵、审核报告、渲染和版本清单通过人工验收。
- 内容门槛：扩大整本写作前，代表章节通过写前方案、细目录、内容展开和客户表述验收；记录首稿实质改写与重复缺陷，不能只统计生成完成量。
- 收益目标：对照增强版 Codex＋Skill，在同等验收标准下减少人工处理时间；降低 30% 是待验证目标，不是承诺。
- 独立验收：至少一个未参与规则调试的项目验证泛化；样本不足时结论标注为有限试点结果。

## 9. 真实试点需要的输入

| 输入 | 最迟需要的阶段 | 缺失时处理 |
|---|---|---|
| 行业、产品、卷册与招标/补遗样本 | 解析与要求抽取的业务验收前 | 可开发通用结构和合成测试，不声称业务准确率 |
| 企业事实、资质、案例、历史标书和交付模板 | 证据检索及写作业务验收前 | 可开发缺口流程，不伪造企业材料 |
| 模型提供商、模型名、向量模型、允许发送的数据范围和费用上限 | 真实模型接入前 | 可完成接口契约和替身测试，不执行真实资料调用 |
| 事实确认人与标书评审人 | 大纲/小样及最终验收前 | 不将模型意见登记为人工确认 |
| 未参与调试的独立项目 | 对照评估前 | 可完成现有样本测试，不宣称已验证泛化和 ROI |

当前工作区已核对：只有既有 Skill、辅助脚本、研究和需求文档，尚未发现上述业务材料或独立应用工程。
