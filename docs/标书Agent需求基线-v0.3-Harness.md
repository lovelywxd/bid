# 专用标书 Agent 需求基线 v0.3-Harness

日期：2026-11-12。状态：规划基线，尚未实现和试点验证。主实施文件为[实施计划 v0.2-Harness](标书Agent实施计划-v0.2-Harness.md)。

## 1. 生效与取代关系

本基线以[需求规格 v0.2](标书Agent需求规格-v0.2.md)全部 F01—F24、T01—T30 为业务需求，编号和原场景不变；补充以下已确定方向与范围解释。旧规格中的首版假设不是已验证结果。与旧技术描述冲突处，以本基线和新实施计划为准。

- 正式采用 DeepSeek Harness 作为唯一 Agent 执行底座；自建专用标书系统，不将“采用底座”继续作为主线选择题。工程、真实章节、整本、留出和每份人工放行门保留。
- 取消实施计划 v0.1 的 LangGraph/checkpointer 与直接正文 ModelGateway 计划，不同时建设双编排/双重试；业务任务库/租约/状态、检索与embedding、事实/验收/交付权威继续自建。
- 交付目标是完整业务链和经过验收的整本技术卷；三类章节是扩大整本之前的最小真实闭环，不是最终产品范围。
- 全项目技术、资格、商务、附件、报价和签署要求都提取核对。生成、校验和用户外部责任明确分开；技术卷放行不等于整套投标文件就绪，更不等于签署/提交成功。详见新计划 1.3。
- 增加整体投标响应策略和总体方案的显式产物，前接要求/证据/缺口，后接大纲/细目录/章节写前设计；F06/F23 涵盖，不另造重复需求编号。
- 五类陈述分开：已有事实、项目决定、基于事实合理展开、未知、偏离。招标需求不能证明产品支持，项目决定不能把计划开发改成已有能力；F05/F07/F24 继续负责。
- F18 的关键字段保留和交接优先通过权威状态重建＋按条款组新 session 实现，首版移除默认英文编程压缩/失败继续；不要求先自建完整原位压缩内核。
- F13/F16/F20 增强工程验收：实际 HTTP 发送、重试/摘要/内部重发、外发元数据、取消/活动超时、租约/幂等及跨会话预算都需要证据，SDK completed 不等于产物合格。

## 2. 保留的用户质量目标

资料完备时尽量首稿达到正式使用所需质量；可检查的方案、围绕完整业务问题的细目录、必要过程/规则的充分解释、有据正负承诺和客户语言是必需目标。不能以字数、关键词、模型高分、文件生成或采用新底座代替质量验收。语言编辑保留真实否定、例外和范围；设计错误回设计，不能只润色。

长期企业知识发布和项目固定选库、对象对话/工作台、事实/决定/经验确认、人工新稿/锁定保护、补遗失效、共享预算、逐层验收和人工最终放行均保留。每份文件都按当前版本检查；真实模型与业务效果未验证不能伪报。
